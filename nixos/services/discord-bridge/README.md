# Minecraft Discord Bridge (`nixos/services/discord-bridge/`)

NixOS service module integrating the Go-based [minecraft-discord-bridge](https://github.com/t3u-tsu/minecraft-discord-bridge) for automated Discord-Minecraft player whitelist management.

## Module Architecture

- Builds from the `minecraft-discord-bridge` flake input package.
- Exposes a local UNIX domain socket at `/run/minecraft-discord-bridge/bridge.sock` for operator queries.
- Operates under a dedicated unprivileged `minecraft` user and group for privilege separation.
- Injects Discord bot tokens from a SOPS environment file, and reads server RCON passwords from local secret files at start through `environmentSecretFiles`.

## Configuration Example

```nix
my.services.minecraft-discord-bridge = {
  enable = true;
  settings = {
    discord.admin_guild_id = "1457...";
    database.path = "/var/lib/minecraft-discord-bridge/bridge.db";
    bridge.socket_path = "/run/minecraft-discord-bridge/bridge.sock";
    servers.nitac23s = {
      network = "tcp";
      address = "127.0.0.1:25575";
      whitelist_path = "/srv/minecraft/nitac23s/whitelist.json";
    };
  };
  environmentFiles = [ config.sops.secrets.discord_bridge_env.path ];
  environmentSecretFiles.RCON_PASS_nitac23s = config.my.services.minecraft.rconSecretPath;
};
```

`environmentSecretFiles` maps environment variable names to files that the launcher reads with `cat` before `exec`-ing the bridge, so the values never enter the world-readable Nix store. The RCON file is generated by `minecraft-secrets.service` and owned by the `minecraft` user the bridge runs as ([minecraft/README.md](../minecraft/README.md#local-secrets)).

## CLI Operations

Communicate with the running daemon over its UNIX domain socket using `nc`:

```bash
# Query daemon status
echo 'status' | sudo nc -U -N /run/minecraft-discord-bridge/bridge.sock

# Generate an invitation token for a guild
echo 'invite-create nitac23s' | sudo nc -U -N /run/minecraft-discord-bridge/bridge.sock
```
