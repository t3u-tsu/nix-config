# Encrypted Secrets (`secrets/`)

Agenix-rekey secrets encrypted with age. Secrets are stored in master definition files encrypted for the offline master identity, and rekeyed per host for distribution and pure Flake evaluations. Never commit plaintext secrets to version control.

## Directory Structure

```text
secrets/
├── master/                          # Master-encrypted secrets (offline Bitwarden recipient)
│   ├── common/                      # Fleet-wide secrets
│   │   └── deploy_key.age           # GitHub private repository deploy key
│   ├── hosts/<hostname>/            # Host-specific secrets
│   │   ├── user_password_hash.age   # User password hash
│   │   ├── nebula_key.age           # Nebula mesh VPN node private key
│   │   └── emergency_ssh_token.age  # Cloudflare Tunnel authentication token
│   └── services/<service>/          # Service-specific secrets
│       ├── backup/                  # Restic backup (password.age, ssh_key.age)
│       ├── ddns/                    # Cloudflare DDNS (cloudflare_api.env.age)
│       ├── discord-bridge/          # Discord bot token (bridge.env.age)
│       ├── signing/                 # Git commit signing GPG key (gpg_private_key.age)
│       └── conoha-vps-mcp/          # ConoHa API credentials (credentials.env.age)
└── rekeyed/                         # Age files generated by agenix-rekey (committed to Git)
    ├── home/<hostname>/<username>/  # home-manager secrets (decrypted with the user SSH key)
    └── hosts/<hostname>/            # NixOS host secrets (decrypted with the host SSH key)
```

| Directory / File | Scope | Description |
| :--- | :--- | :--- |
| `master/common/` | Fleet-wide | Secrets shared across all machines (deploy key for `nix-config-private`). |
| `master/hosts/<hostname>/` | Host-specific | User password hashes, Nebula private keys, emergency tokens. |
| `master/services/<service>/` | Service-specific | Service secrets (Cloudflare DDNS, Restic, Discord bridge, commit signing, ConoHa API). |
| `rekeyed/hosts/<hostname>/` | Host-specific | Auto-generated `<hash>-<name>.age` files encrypted for the target host SSH key. Tracked in Git for offline and CI builds. |
| `rekeyed/home/<hostname>/<username>/` | Host & user | Auto-generated `<hash>-<name>.age` files encrypted for the user SSH key used by home-manager. Tracked in Git. |

The `rekeyed/` tree is generated by `just secret rekey` from the `master/` files.

Plaintext files and runtime credentials outside `secrets/`:
- Nebula root CA certificate: [nixos/networking/nebula/ca.crt](../nixos/networking/nebula/ca.crt) (public, unencrypted).
- Nebula node certificates: `hosts/<hostname>/nebula.crt` (public, unencrypted).
- Minecraft forwarding secret and RCON password: generated on `shosoin-tan` in `/var/lib/minecraft/secrets/` (`forwarding.secret`, `nitac23s-rcon.secret`) by `minecraft-secrets.service` at service start with `openssl rand`.

## Defense in Depth and Key Model

| Layer | Environment | Storage / Mechanism | Purpose |
| :--- | :--- | :--- | :--- |
| Layer 1: Bitwarden Vault | Bitwarden (`nix-config/`) | Secure Notes & SSH Keys | Offline isolation of `agenix-master-key`, `nebula-ca/ca.key`, user SSH keys (`ssh/<hostname>`), and failover host key (`ssh/torii-chan`). |
| Layer 2: Ephemeral RAM | Operator machine (`/run/agenix-master/`) | Dedicated noswap tmpfs, key mode 0400 & exit trap | Ephemeral identity storage during operator commands. Discarded immediately on exit. |
| Layer 3: agenix-rekey | Git repository (`secrets/master/`) | Nix module dependency resolution | Resolves host bindings and rekeys master secrets per target host. |
| Layer 4: Target Runtime | Fleet machines (`/run/agenix/`) | SSH host key (`/etc/ssh/ssh_host_ed25519_key`) or user SSH key (`~/.ssh/id_ed25519`) | Decrypts only the host's `secrets/rekeyed/hosts/<hostname>/*.age` files and the user's `secrets/rekeyed/home/<hostname>/<username>/*.age` files. |

### Bitwarden Vault Layout

- `nix-config/agenix-master-key` (Secure Note): Primary age secret key (`AGE-SECRET-KEY-1...`).
- `nix-config/nebula-ca/ca.key` (Secure Note): Disaster recovery backup of the offline Nebula root CA private key.
- `nix-config/ssh/<hostname>` (SSH Key): User SSH keys (`id_ed25519` for `BrokenPC`, `x1c7`) and the `torii-chan` SSH host key (`ssh_host_ed25519_key`) for VPS failover.

## CLI Index

Secret operations are exposed via `just secret <recipe>` ([just/secret.just](../just/secret.just)), backed by [scripts/secrets/](../scripts/secrets/). See [docs/operations/secret-management.md](../docs/operations/secret-management.md) for the full Bitwarden, age, staged import, password rotation, and SSH key backup/restore procedures.

```bash
just secret unlock                                        # Start in-memory Bitwarden session agent
just secret rekey                                         # Rekey master secrets for all hosts
just secret edit secrets/master/services/ddns/cloudflare_api.env.age
just secret apply-staging [--dry-run | --no-rekey]        # Encrypt .secrets-staging/ into secrets/master/
just secret set-host-password [--all | <host>...]         # Update user_password_hash.age
just secret ssh-restore [hostname] [--force]              # Restore ~/.ssh/id_ed25519 from Bitwarden
just secret ssh-backup [hostname] [--force]               # Back up ~/.ssh/id_ed25519 to Bitwarden
just secret doctor                                        # Verify tools, master key, SSH key, and vault state
just secret lock                                          # Purge agent memory and lock Bitwarden
```
